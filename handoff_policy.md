# Правило передачи заявки

Бот собирает запрос без повторных вопросов. После просьбы о смете или завершения сбора информации он один раз показывает компактное резюме текущего проекта: известные дату, место, программу, оборудование и пожелания.

Технические решения принимает сотрудник, а не бот.

Telegram Business: менеджер видит переписку; нельзя утверждать об отдельном уведомлении без факта отправки.

MAX: сообщение «передано менеджеру» только после подтвержденного уведомления. Контакт запрашивается по правилам платформы.

При нескольких заказах сведения не смешиваются. Исторические редакции хранятся в CHANGELOG, действующее правило должно быть единым.

## Разговор без повторения заявки — кейс «свадьба в Горпарке»
- Если клиент уже указал формат «свадьба», не задавать вопросы про презентации и не уточнять назначение экрана как для конференции. Видео и слайд-шоу являются понятным запросом.
- Не пересказывать весь комплект и место после каждого сообщения. Уточнять только действительно неизвестные ключевые сведения; не повторять вопрос, даже если он был в позапрошлом сообщении.
- Если известны формат, площадка, дата, состав услуг, количество гостей для звука и назначение экрана, считать вводные достаточными для передачи специалисту. Не продолжать расспрос про время, технические характеристики или дополнительные предпочтения без инициативы клиента.
- Завершающий ответ один раз: «Данные для предварительного расчёта собраны. Андрей видит переписку и сможет подготовить предложение» и краткое резюме. Не объявлять о реально отправленном уведомлении, если оно не отправлено.
- Дата «22 июля» без указанного года: сохранить число и месяц без выдумывания года; при необходимости менеджер уточнит год.
